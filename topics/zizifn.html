راهنمای جامع راه‌اندازی و دپلوی پروژه ​

آموزش گام‌به‌گام فورک کردن، پیکربندی سکرت‌های امنیتی، اجرای گیت‌هاب اکشن و دریافت لینک‌های اشتراک کانفیگ VLESS



پروژه zizifn یک کانفیگ پروکسی امن بر پایه پروتکل VLESS-WS-TLS/TCP است که بخش پردازش هدر پروتکل اون با زبان Rust نوشته شده و با وب‌اسمبلی (Wasm) کامپایل میشه، و به کمک ابزار Wrangler روی ورکر کلودفلر اجرا میشه. برای اینکه بتونی این پروژه رو روی اکانت خودت پیاده‌سازی کنی، مراحل زیر رو گام‌به‌گام دنبال کن.

چیزایی که تو نسخه‌ی جدید داره:

  • زنجیره‌ی فالبک: اتصال مستقیم ← پروکسی‌آی‌پی ← NAT64
  • انتخاب پروکسی‌آی‌پی بر اساس کشور و امتیاز ریسک، مستقیم از داخل پنل
  • دپلوی همزمان روی ۴ اکانت کلودفلر با یه بار اجرای اکشن، با اسم و پروکسی‌آی‌پی و uuid دلخواه برای هر وورکر
  • گزینه‌ی باز شدن Google AI Studio و Gemini با یه تیک موقع دپلوی
  • لینک ساب Enhanced مناسب شرایط اینترنت ایران برای کلاینت‌های PattNG و v2rayNG.
  • ساب اختصاصی Clash Meta و ساخت کانفیگ فرگمنت (PattNG) داخل پنل.

درباره‌ی خطاهای 1101 و 1102 کلودفلر

خطای 1101 یعنی کد وورکر موقع اجرا exception داده، و 1102 یعنی وورکر از محدودیت منابع (CPU یا حافظه) رد شده. این‌ها خطاهای زمان اجرا هستن، نه اینکه کلودفلر چیزی رو شناسایی یا مسدود کرده باشه. اگه به یکی‌شون خوردی، بخش عیب‌یابی رو ببین.

نکته مهم

دو متغیر اول (آی‌دی و توکن کلودفلر) اجباری هستن، یعنی بدون اونا نمیشه وورکر رو دپلوی کرد. بقیه اختیاری هستن، ولی درباره‌ی UUID یه نکته‌ی امنیتی هست:

  • اگه موقع اجرای دستی اکشن (گام چهارم) فیلد UUID رو خالی بذاری و سکرت UUID هم نداشته باشی، اکشن خودش یه UUID رندوم میسازه.
  • ولی با هر push به main، اگه سکرت UUID نداشته باشی، از UUID پیش‌فرضی استفاده میشه که تو ریپوی عمومی همه می‌بینن. یعنی هر کسی میتونه پنل و پروکسی تو رو باز کنه. پس حتماً یه UUID مخصوص خودت تو سکرت UUID بذار. اکشن هم تو لاگ یه هشدار نشونت میده که از UUID عمومی استفاده شده.

برای دیدن UUID ساخته‌شده باید وارد داشبورد کلودفلر بشی، وورکر مورد نظر رو باز کنی و تو تب تنظیمات (Settings) بخش Variables and Secrets رو ببینی.

متغیرهای یک‌بار مصرف

مقادیری که تو فرم پاپ‌آپ موقع Run workflow وارد می‌کنی کاملا یک‌بار مصرف هستن و تو تنظیمات ریپازیتوری ذخیره نمیشن. این قابلیت برای تست سریع پروکسی‌آی‌پی‌های مختلف یا عوض کردن سریع UUID با ساخت وورکر جدید کاربردیه.


جزئیات کار بعد از کلیک روی Run workflow، گیت‌هاب یه سرور ابری راه میندازه، کامپایلر Rust و ابزار wasm-pack رو نصب میکنه و کدها رو کامپایل میکنه. چند لحظه بعد از تموم شدن کامپایل، یه Worker جدید با اسم 0x00 تو اکانت کلودفلرت ساخته می‌شه (یا با هر اسمی که تو فرم یا سکرت تعیین گرده باشی).

اگه میخوای اسم پیش‌فرض وورکر رو دائمی عوض کنی، می‌تونی از سطر اول فایل wrangler.toml تو مخزن این کار رو بکنی و یا از طریق سکرت‌ها که پایین‌تر توضیح میدم.

توجه

عوض کردن اسم وورکر یعنی یه وورکر جدید با آدرس workers.dev جدید ساخته میشه. وورکر قبلی با آدرس قبلی تو داشبورد میمونه و باید خودت پاکش کنی.

گام پنجم (اختیاری): دپلوی روی چند اکانت ​

اگه بیشتر از یه اکانت کلودفلر داری، میتونی با یه بار اجرای اکشن، همین وورکر رو روی حداکثر ۴ اکانت دپلوی کنی. هر اکانت یه «اسلات» داره (۱ تا ۴) و هر اسلات سکرت‌های خودش رو میخونه.

قاعده‌ی اسم سکرت‌ها: اسلات ۱ از همون اسم‌های ساده‌ی قبلی استفاده میکنه (CLOUDFLARE_API_TOKEN و بقیه)، پس اگه فقط یه اکانت داری هیچ چیزی عوض نمی‌شه. اسلات ۲ به بعد همون اسم‌ها رو با پسوند _N دارن، که N شماره‌ی اسلاته:

اضافه کردن اکانت جدید ​

۱. تو ریپازیتوری برو به Settings ← Secrets and variables ← Actions.

۲. دو سکرت CLOUDFLARE_API_TOKEN_N و CLOUDFLARE_ACCOUNT_ID_N رو بساز (N شماره‌ی اسلات خالیه، یعنی ۲ و ۳ و ۴).

۳. (اختیاری) یه Variable (نه Secret) به اسم CLOUDFLARE_ACCOUNT_N_LABEL بساز و یه اسم خوانا بهش بده، مثلاً Personal یا Client-A. این اسم تو نام مرحله‌ی دپلوی و صفحه‌ی خلاصه نمایش داده میشه. برای ساختنش به تب Variables تو همون صفحه برو. اگه نذاریش، اسم پیش‌فرض Account N استفاده میشه.

۴. (اختیاری) اگه این اکانت باید UUID یا PROXYIP یا اسم وورکر متفاوتی داشته باشه، سکرت‌های UUID_N و PROXYIP_N و WORKERNAME_N رو هم اضافه کن.

۵. دفعه‌ی بعد که اکشن رو دستی اجرا میکنی، چک‌باکس همون اکانت رو تیک بزن.

مشاهده اسکرین‌شات

اسم دلخواه برای هر وورکر ​

تو فرم Run workflow، فیلد Worker names رو به ترتیب اسلات‌ها پر کن و با کاما از هم جداشون کن. مثلاً اگه اکانت‌های ۱ و ۳ رو تیک زدی و میخوای اسم‌هاشون alpha و gamma باشه:

text
alpha,,gamma
1

جایگاه خالی (وسط دو کاما) یعنی «برای این اکانت از سکرت یا اسم پیش‌فرض استفاده کن». اسم‌ها فقط باید حروف کوچک انگلیسی، عدد و خط تیره باشن، وگرنه اکشن با خطای Invalid worker name متوقف میشه.

وقتی یه مقدار از چند جا می‌تونه بیاد، کدوم اعمال میشه؟ ​

همیشه اولین مورد از بالا برنده‌ست:

تنظیماولویت
اسم وورکرفیلد Worker names (به ترتیب اسلات) ← سکرت WORKERNAME یا WORKERNAME_N ← اسم داخل wrangler.toml
UUIDفیلد UUID تو فرم ← سکرت UUID_N ← سکرت UUID ← UUID رندوم (اجرای دستی) یا UUID عمومی پیش‌فرض (push)
پروکسی‌آی‌پیفیلد Proxy IP تو فرم ← سکرت PROXYIP_N ← سکرت PROXYIP ← di.nscl.ir

چند نکته‌ی کاربردی

  • اسلاتی که تیک نخورده، کلا نادیده گرفته میشه. پس لازم نیست برای اسلات‌های خالی چیزی بذاری.
  • اگه اسلاتی رو تیک بزنی ولی سکرت‌های اجباریش رو نساخته باشی، همون اسلات با یه خطای واضح fail میشه ولی بقیه‌ی اکانت‌ها بدون مشکل دپلوی میشن.
  • با push معمولی به main فقط اکانت ۱ دپلوی میشه.
  • اگه فیلد UUID فرم رو پر کنی، همون UUID برای همه‌ی اکانت‌های تیک‌خورده اعمال میشه. اگه خالی بذاری و سکرتی هم نباشه، هر اکانت یه UUID رندوم جدا می‌گیره.

گام ششم (اختیاری): باز شدن Google AI Studio و Gemini ​

وقتی Placement وورکر روی حالت پیش‌فرض باشه، وورکر نزدیک کاربر اجرا میشه و از بعضی لوکیشن‌ها سایت Google AI Studio و Gemini از طریق اتصال به کانفیگ باز نمیشن. اگه این مشکل رو داری، موقع اجرای اکشن این گزینه رو تیک بزن:

Unlock Google AI Studio & Gemini

یا اگه میخوای همیشه فعال باشه، سکرت ENABLE_GEMINI رو روی true بذار.

وقتی فعال باشه، اکشن موقع دپلوی این تنظیم رو به wrangler.toml اضافه میکنه:

toml
[placement]
region = "gcp:us-central1"
1
2

یعنی وورکر رو تو Google Cloud (ناحیه‌ی us-central1 آمریکا) اجرا می‌کنه و به همین دلیل Gemini و AI Studio بدون مشکل باز میشن.

توجه

چون وورکر به‌جای نزدیک‌ترین لوکیشن (ترکیه، امارات، آلمان) می‌ره و تو آمریکا اجرا میشه، پینگ ممکنه کمی بالاتر بره. اگه به سرویس‌های گوگل نیاز نداری، این گزینه رو خاموش بذار.

برای اطمینان از اعمال شدن، تو داشبورد کلودفلر وارد وورکر شو و تو تنظیمات (Settings) بخش Placement رو ببین.

مشاهده اسکرین‌شات

اگه میخوای این تنظیم رو دستی و از داخل داشبورد کلودفلر انجام بدی، دوست عزیزمون مهدی تو این مقاله کامل توضیح داده.


نحوه استفاده ​

دسترسی به پنل مدیریت ​

بعد از دپلوی، کافیه UUID خودت رو به انتهای آدرس وورکرت اضافه کنی:

https://Your-workers.dev-URL/<UUID>

برای مثال:

https://0x00.workers.dev/be0ff9df-1468-41a0-8865-796d1c6800db

اگه UUID نذاشته باشی و آدرس وورکر رو بدون UUID باز کنی، یه صفحه‌ی ۴۰۴ میبینی که توضیح میده UUID لازمه و یه دکمه هم برای رفتن به تنظیمات وورکرت تو کلودفلر داره.

برای دیدن UUID: داشبورد کلودفلر ← Workers & Pages ← وورکر مورد نظر ← Settings ← Variables and Secrets.


دریافت لینک اشتراک (Subscription) ​

لینک اشتراک شامل ده‌ها کانفیگ هست: دامنه‌های مختلف، آی‌پی‌های تمیز کلودفلر، یه کانفیگ NAT64 و کانفیگ‌های پروکسی‌آی‌پی کم‌ریسک. این کانفیگ‌ها با اسم کشور، نوع هاست و پروتکل برچسب‌گذاری میشن، مثلاً:

🇺🇸US-Domain-1-TLS

برای دریافت لینک ساب به‌صورت خودکار از دکمه‌های Import to ... داخل پنل استفاده کن.

و اگه لینک ساب رو دستی میخوای تا تو کلاینت‌های دیگه استفاده کنی، کافیه انگشتت رو چند ثانیه روی یکی از دکمه‌های Import to ... نگه داری (Long Touch). مرورگر ازت اجازه‌ی کپی کردن لینک رو میخواد (فقط یک‌بار برای همیشه)، با کلیک روی Allow لینک ساب همون کلاینت برات کپی میشه.

مشاهده اسکرین‌شات

لینک ساب برای مثال: ​

For Xray Core clients:
https://0x00.workers.dev/xray/be0ff9df-1468-41a0-8865-796d1c6800db

For Singbox core clients:
https://0x00.workers.dev/sb/be0ff9df-1468-41a0-8865-796d1c6800db

For Clash Meta (mihomo) clients:
https://0x00.workers.dev/clash/be0ff9df-1468-41a0-8865-796d1c6800db

For PattNG Client:
https://0x00.workers.dev/xray-enhanced/be0ff9df-1468-41a0-8865-796d1c6800db

تو همه‌ی این لینک‌ها میتونی با اضافه کردن ?name= یه اسم دلخواه برای ساب تعیین کنی. اسم فارسی هم پشتیبانی میشه.


برخی از قابلیت‌های پنل ​

اطلاعات شبکه ​

بالای پنل دو کارت میبینی: Proxy Server (اطلاعات هاست پروکسی‌آی‌پی) و Your Connection (اطلاعات اتصال خودت، شامل آی‌پی، لوکیشن، ISP و امتیاز ریسک). دکمه‌ی Refresh اطلاعات رو دوباره میگیره. اگه سرویس امتیاز ریسک جواب نده، به‌جای یه عدد گمراه‌کننده، N/A نمایش داده میشه.

مشاهده اسکرین‌شات

کارت Xray Core Clients ​

کانفیگ اصلی و دکمه‌های Import برای Exclave، V2rayNG، Clash و Hiddify اینجاست. دو نکته:

  • با زدن Import to V2rayNG یه پنجره باز میشه که نوع ساب رو میپرسه: Normal یا Enhanced (مخصوص PattNG).
  • با زدن Import to Hiddify یه یادآوری میاد که برای کار کردن کانفیگ باید Remote DNS رو تو برنامه‌ی Hiddify از tcp://8.8.8.8 به https://8.8.8.8/dns-query تغییر بدی.

فالبک NAT64 ​

ترتیب اتصال وورکر اینطوریه:

Direct connection → ProxyIP pool → NAT64

اگه اتصال مستقیم و همه‌ی پروکسی‌آی‌پی‌ها شکست بخورن و دیتایی برنگردونن، وورکر آدرس مقصد رو به IPv4 تبدیل میکنه، اون رو داخل یه آدرس 64:ff9b::/96 میذاره و از طریق گیت‌وی NAT64 کلودفلر وصل میشه. این آخرین راه نجاته، مخصوصاً وقتی که پروکسی‌آی‌پی‌ها از کار افتادن.

  • به‌صورت پیش‌فرض روشنه. برای خاموش کردن کلی، متغیر NAT64 رو روی off بذار.
  • تو پنل کارت NAT64 Fallback یه سوییچ داره که تعیین میکنه کانفیگی که کپی میکنی NAT64 روشن داشته باشه یا خاموش (پارامتر ?nat64=on یا ?nat64=off تو path کانفیگ).
  • تو ساب‌ها هم یه کانفیگ NAT64 قرار داده میشه.
مشاهده اسکرین‌شات

انتخاب پروکسی‌آی‌پی دلخواه ​

این کارت وسط پنل لیست پروکسی‌آی‌پی‌های در دسترس رو بر اساس کشور نشون میده، با امتیاز ریسک هر آی‌پی:

۱. یه کشور رو انتخاب کن (مثلا ترکیه).

۲. یکی یا چند آی‌پی رو تیک بزن.

۳. کانفیگ Xray یا Singbox اون آی‌پی رو کپی کن، یا با دکمه‌های Copy Xray و Copy Singbox بالای لیست همه‌ی آی‌پی‌های تیک‌خورده رو یکجا کپی کن.

هر کانفیگی که از اینجا کپی میکنی، تو path خودش یه پارامتر proxyip داره که اون آی‌پی رو فقط برای همون کانفیگ به‌عنوان مسیر فالبک تعیین میکنه. پس با یه کلیک پروکسی‌آی‌پی کشور دلخواهت رو داری.

رنگ نشان ریسک: سبز یعنی ریسک پایین، زرد متوسط، قرمز بالا. دکمه‌ی Refresh لیست رو دوباره از سرور میگیره و کش رو دور میزنه.

مشاهده اسکرین‌شات

درباره‌ی کش

نتیجه‌ی جستجوی پروکسی‌آی‌پی‌ها ۶ ساعت کش میشه. روی آدرس‌های *.workers.dev کش کلودفلر کار نمیکنه، پس اونجا لیست هر بار دوباره گرفته میشه و ممکنه کمی کندتر باشه. با یه دامنه‌ی شخصی این مشکل رو نداری.

فرگمنت بیلدر (Fragment Builder) ​

برای کلاینت PattNG، این بخش به‌صورت زنده یه کانفیگ حاوی پارامتر‌های fm (Final Mask) و cs (cypher suites) با fingerprint: unsafe رو برات می‌سازه:

  • سه پریست: Default، Aggressive و Custom.
  • میتونی فرگمنت اضافه، حذف و جابجا کنی، و مقدارهای packets، lengths، delays و maxSplit هر کدوم رو دستی تغییر بدی.
  • با انتخاب Fingerprint و دکمه‌ی کپی، کانفیگ نهایی آماده‌ی استفاده تو PattNG میشه.
  • دکمه‌های Visual و JSON نمای پیش‌نمایش رو عوض میکنن، و Reset to Default همه‌چیز رو به حالت اول برمیگردونه.
مشاهده اسکرین‌شات

آی‌پی تمیز دلخواه (Custom Clean IPs) ​

پایین پنل لینک Define Custom Clean IPs هست. آی‌پی یا دامنه‌های تمیز خودت رو (هر کدوم تو یه خط، با پورت اختیاری مثل 188.114.97.6:8443) واردش کن و روی Save & Generate بزن. پنل برای هر کدوم یه کانفیگ Xray و یه کانفیگ Singbox میسازه. این لیست فقط تو مرورگر خودت ذخیره میشه و جایی ارسال نمیشه.

مشاهده اسکرین‌شات


توضیحات بیشتر ​


تفاوت xray و xray-enhanced و sb و clash

عبارت xray ​

مناسب کلاینت‌هایی که از هسته‌ی Xray استفاده میکنن، مثل:

v2rayNG, v2rayN MahsaNG, PattNG Hiddify, v2box, Nekoray, Streisand, Napsternet, NPVT, Happ, and etc.

عبارت xray-enhanced ​

دسته‌ای از کانفیگ‌ها که به‌صورت پیش‌فرض پارامترهای پترنی‌ها رو شامل میشن، یعنی Final Mask و Cipher suites و مقدار unsafe برای fingerprint دارن. علاوه بر کانفیگ‌های TLS، نسخه‌های TCP (بدون TLS) هم داخلشه، برای کلاینت‌هایی که ازشون پشتیبانی میکنن.

مناسب کلاینت‌هایی که از هسته‌ی Xray استفاده کرده و این پارامترهارو هندل میکنن، مثل:

PattNG, v2rayNG

عبارت sb ​

مناسب کلاینت‌هایی که از هسته‌ی SingBox استفاده میکنن، مثل:

Nekobox, Exclave, Singbox, Husi, Karing, and etc.

عبارت clash ​

یه کانفیگ کامل Clash Meta (mihomo) که مستقیم از خود وورکر ساخته میشه و نیازی به سرویس خارجی (subconverter) نداره.


آی‌پی تمیز کلودفلر ​

آی‌پی‌های داخل کانفیگ‌ها از مخزن آی‌پی تمیز NiREvil/vless تامین میشه، سیکل بروزرسانی آی‌پی‌ها: هر ۴ ساعت.


کانفیگ‌های بهینه‌شده

اخیراً پترنی‌ها برای رفع اختلال‌ها و قطع و وصلی‌های پیاپی (به‌خاطر وضعیت کصشعر اینترنت ایران) و همچنین رفع مشکل پایین بودن سرعت آپلود تو کانفیگ‌های ساخته‌شده با وورکر کلودفلر، پیشنهاد دادن که دو پارامتر به کانفیگ‌ها اضافه کنیم:

  • Final Mask
  • Cipher suites

برای اینکه عملکرد کانفیگ‌ها هرچه بهتر بشه، یه فورک از v2rayNG با اسم PattNG هم رو گیت‌هاب خودشون منتشر کردن. برای همین کنار کانفیگ‌های نرمال v2rayNG یه ساب دیگه با اسم Enhanced داریم که کانفیگ‌ها رو آماده و همراه این پارامترهای جدید وارد کلاینتت میکنه.

برای استفاده، اول باید کلاینت PattNG رو از مخزن گیت‌هاب پترنی‌ها دانلود و نصب کنی، بعد از داخل پنل روی Import to v2rayNG کلیک کنی و Enhanced رو انتخاب کنی.

عیب‌یابی ​

مشکلعلت و راه‌حل
خطای No Cloudflare account selectedهیچ چک‌باکس اکانتی تیک نخورده. حداقل یکی رو تیک بزن و دوباره اجرا کن.
خطای Account #N is selected but its ... secrets aren't setاسلات N رو تیک زدی ولی سکرت‌های CLOUDFLARE_API_TOKEN_N و CLOUDFLARE_ACCOUNT_ID_N رو نساختی.
خطای Invalid worker nameاسم وورکر باید فقط حروف کوچک انگلیسی، عدد و خط تیره باشه.
دپلوی با خطای احراز هویت یا توکن fail میشهتوکن باید دسترسی Edit Workers داشته باشه. اگه منقضی شده، یه توکن جدید بساز و سکرت رو عوض کن.
تو لاگ اکشن هشدار UUID عمومی دیدمسکرت UUID رو نذاشتی. یه UUID اختصاصی بساز و تو سکرت‌ها بذار.
پنل صفحه‌ی ۴۰۴ «No UUID found» نشون میدهآدرس رو به شکل https://آدرس-وورکر/<UUID> باز کن.
خطای 1101کد وورکر exception داده. تو داشبورد کلودفلر وارد وورکر شو و بخش Logs رو باز کن (یا wrangler tail اجرا کن) و پیام خطا و stack trace رو بخون.
خطای 1102وورکر از محدودیت CPU یا حافظه رد شده. تو لاگ‌ها بخش مصرف منابع رو ببین.
امتیاز ریسک N/A نشون میدهسرویس امتیاز ریسک پاسخ نداده. بقیه‌ی پنل کار میکنه و بعد از چند دقیقه دوباره تلاش میشه.
Gemini یا Google AI Studio باز نمیشهگزینه‌ی Unlock Google AI Studio & Gemini رو تیک بزن و دوباره دپلوی کن. گام ششم
لیست ProxyIPs خالیه یا دیر میاددکمه‌ی Refresh رو بزن. تو آدرس‌های workers.dev کش کار نمیکنه و لیست هر بار دوباره گرفته میشه.
